--- CLAUDE ---
A "door" is one firewall rule on the OpenWrt One. Traffic that arrives through WireGuard lands in the router's `remote` zone, and that zone blocks everything by default. Each door lets one tunnel peer reach one machine on one port. There are two doors today:

- **Cleotilde-Door-Continuity:** your phone (`10.98.0.2`) can reach factory2 (`192.168.1.138`) on port 80. This is how Continuity worked from 4G.
- **Cleotilde-Door-FactoryChat:** Paula3 (`10.98.0.3`) can reach factory2 on port 1883 (the chat broker).

The new door would be one more rule like those:

- **Cleotilde-Door-PhotoChat:** your phone (`10.98.0.2`) can reach this computer (`192.168.1.125`) on port 8899, the photo page.

On the router it is:

```
uci set firewall.door_photochat=rule
uci set firewall.door_photochat.name='Cleotilde-Door-PhotoChat'
uci set firewall.door_photochat.src='remote'
uci set firewall.door_photochat.src_ip='10.98.0.2'
uci set firewall.door_photochat.dest='lan'
uci set firewall.door_photochat.dest_ip='192.168.1.125'
uci set firewall.door_photochat.proto='tcp'
uci set firewall.door_photochat.dest_port='8899'
uci set firewall.door_photochat.target='ACCEPT'
uci commit firewall
/etc/init.d/firewall reload
```

It changes nothing else:
- Only your phone's tunnel address gets through, not Paula3 and not anyone on the internet.
- Only port 8899 on this computer opens, not SSH or anything else on it.
- The firewall reload takes about a second and doesn't touch Wi-Fi or the network.
- Undoing it is `uci delete firewall.door_photochat; uci commit firewall; /etc/init.d/firewall reload`.

Without this rule, the router drops the phone's request before it reaches this computer, even with WireGuard on.
